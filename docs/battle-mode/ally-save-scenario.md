# BATTLE MODE 追加演出仕様：ally_save（カイ援軍）

> **ステータス：オーナー合意済み（2026-11-14）**
>
> 本書は `ally_save` 専用の画像設計・場面進行を定める正本。
> [BATTLE MODE 基本演出仕様](battle-mode-basic-structure.md) の**基本14枚に追加する専用画像4枚**を扱う。
> 基本14枚の枚数・他の演出シナリオは変更しない。

## 1. シナリオの核心

敵ヴォルグが先制して必殺技を繰り出すが、**6Gでカイが登場し、7Gで攻撃を受け流して主人公を救う**。
8Gはカイ・主人公・ヴォルグの三者の余韻を描き、**8G終了後、カイが主人公の肩を叩いて次ROUNDへの継続を告知する**。

- **カイは敵を倒さない。主人公もこのシナリオ内で反撃しない。**
- ヴォルグの攻撃は主人公に命中しない。**7Gでカイが攻撃の軌道を逸らす**ことによって助かる。
- セリーヌ復活とは別シナリオ。カイ援軍ルートにセリーヌを登場させない。
- 基本仕様の「8Gでひとつの攻防」という原則を守る。
- キャラクターの外見は [正式ガイド](../characters/README.md) に従う。カイは [kai.png](../characters/design-guides/kai.png)、主人公は [protagonist.png](../characters/design-guides/protagonist.png)、ヴォルグは [volg.png](../characters/design-guides/volg.png) を確認する。

**最終結果の肩叩き画像は8G中に先出ししない。** 8Gの継続条件を満たし、8G終了後の結果告知フェーズで表示する。

## 3. 新規画像4枚の設計

以下の4枚を制作する。**このシナリオに必要な新規画像は4枚**。既存の基本14枚は差し替えず、1G〜5Gではそのまま使用する。

### ① 6G：カイ登場
- ファイル：`public/battle_ally_g06_kai_arrives.webp`
- ヴォルグの必殺技が主人公に迫るなか、カイが介入する場面。
- 銀髪、深緑のロングコート、灰色のスカーフなど、設定ガイド通りのカイだと一目で分かる。
- **まだ受け流しの成功や敵への攻撃を描かない。** 次の7Gにつながる構図。
- エフェクトは登場時の閃光・短いスピード線・SE程度。カイの立ち絵を画面横断させる擬似格闘アニメは禁止。

### ② 7G：カイが受け流す
- ファイル：`public/battle_ally_g07_kai_parries.webp`
- **ヴォルグ→主人公へ向かう攻撃を、カイが横へ逸らす決定的な瞬間**を完成した一枚絵で描く。
- ヴォルグの攻撃方向、カイの手・腕／身体の動き、主人公の位置関係が明確。
- 正面で受け止める「ガード」や、カイによる「反撃・命中」に見えないこと。
- 接触点にごく短い衝撃フラッシュやSEを合わせる。過剰な人物移動は不要。

### ③ 8G：三者の余韻
- ファイル：`public/battle_ally_g08_trio_afterglow.webp`
- 受け流し後のカイ、助けられた主人公、攻撃を逸らされたヴォルグの**3人を同一画面で**描く。
- カイが流れを変え、主人公が無事で、ヴォルグも健在であることが理解できる構図。
- 余計な追撃、ヴォルグの吹き飛び・撃破、主人公の勝利ポーズを描かない。
- 派手な演出よりも、戦闘後の短い緊張感と静けさを優先。

### ④ 8G終了後：肩叩き／継続告知
- ファイル：`public/battle_ally_result_kai_shoulder_tap.webp`
- カイが主人公の肩を叩き、主人公に次の戦いを託す場面。
- 「次は仕留めろ」という台詞が自然に合う表情・距離・構図。
- ヴォルグの撃破を描かない。結果画像の上に既存の **CONTINUE** 告知を表示できる余白・視認性を確保。
- **画像内に台詞の文字を描き込まない**。VOICE再生はプログラム側で同期する。

### 共通の画像品質要件
- 既存基本画像14枚との画風、光源、闘技場背景、人物の比率・向き、連続するカットの構図を揃える。
- カイの外見は設定ガイドから変更しない。主人公・ヴォルグも同様。
- 静止画自体で出来事が判別できること。CSS transformで人物の演技を捏造しない。
- HUD（ROUND、TOTALなど）や結果エンブレムが顔・重要動作を隠さない構図にする。

## 4. エフェクト・SE・VOICEの扱い

| 場面 | エフェクト・SEの意図 | VOICE |
| --- | --- | --- |
| 1〜5G | 基本の敵先制・敵必殺技の演出を流用 | 既存の敵先制・敵必殺技ボイスを流用 |
| 6G | カイ介入の閃光・登場SE（`kai_arrive`） | 既存の仲間ボイス `voice_fellow`（新規ボイスは要求しない） |
| 7G | 受け流す接触点のフラッシュ、短い衝撃・逸らしSE（`kai_parry`） | なし |
| 8G | 短い余韻（`ally_afterglow`）。過剰なフラッシュを入れない | なし |
| 8G後 | 肩叩きの画面、既存の継続SE（`continue_fanfare`）・CONTINUE表示 | **カイ「次は仕留めろ」**（人間制作の音源 `public/audio/voice_fellow_continue.wav`） |

**VOICE制作・新規音源の生成は実装エージェントの担当外。** 人間側が音源を作成・提供する。

- エージェントは再生タイミングと識別子／接続箇所のみ実装する。仮の音声・TTS・他人の声での代用・無断の音声合成は禁止。
- 音源は `public/audio/voice_fellow_continue.wav` として配置済みで、`src/se.ts` に `voice_fellow_continue` として登録されている。ファイルが無い・読み込めない場合も再生を安全にスキップする（空ファイルや壊れた仮WAVの作成は禁止）。音源を差し替える場合は同じファイル名で上書きする。
- カイ専用VOICEは**8G後の肩叩きカット開始に一度だけ**同期する。CONTINUE・次ROUNDへの遷移で再生が途切れないよう必要な表示タイミングを調整する。
- 敵先制ルートの6Gには主人公被弾VOICE（`voice_hero_damage`）が割り当てられているが、**`ally_save` の6Gでは主人公が被弾したことを示すVOICEを鳴らさず、代わりに `voice_fellow` を再生する**。他シナリオのVOICE挙動は維持する。
- 6G〜8Gでは基本ルートのレバーON時エフェクト（命中・耐える）を `ally_save` には適用しない。
- 現行の表示タイミング（`src/main.tsx`）：8G終了直後に肩叩きカット（`ally_shoulder_tap`）を表示してVOICEを再生 → 1.8秒後に同じ肩叩き画像のままCONTINUE表示（`victory_reveal`）＋継続SE → 3.6秒後に次ROUNDへ遷移。
- VOICEと押し順ナビの既存の再生規則を尊重し、意図しない二重再生を避ける。

## 5. 実装の境界・技術上の注意

- `ally_save` に限り、基本14枚の6G・7G・8G・8G後の画像割当を上記専用4枚に差し替える。
- **1G〜5Gは基本敵先制画像を再利用する。** 他の `hero_attack`、`girl_revive`、`defeat` にカイの絵を表示しない。
- ゲーム数は既存どおり1〜8G。ベット、レバーON、リール停止、押し順成功、払い出しの進行規則を維持する。
- 8Gの次の肩叩きは**継続結果告知の一部**とし、リール操作で勝手に先送りしたり、次ROUND遷移で絵・VOICEを途中終了させたりしない。
- 基本の結果表示は `victory_reveal` を活用してよい。必要な場合は `ally_save` に限って決着表示時間を調整するが、抽選条件や次ROUND移行条件は変更しない。
- 既存の `girl_revive` は現在の `battle_girl_revive.jpg` を流用し、再設計しない。
- 抽選確率、継続率、ストック獲得・消費、小役払出し、押し順ナビ、ROUND進行、他シナリオの表示を変更しない。
- 差し替え後、参照のなくなった**不要画像・旧CSS・旧コード**を調査して削除する。他シナリオで使用中の画像と正式デザインガイドは削除しない。
- コードの型チェック・ビルドは行う。**Playwrightによる画面検証は要求しない**。実装上不可欠な確認に限り、`headless` を明示して最小限の使用を認める。

## 6. 変更管理

- 4枚の画像、6G登場→7G受け流し→8G三者の余韻→8G後肩叩き、という合意済み構成を勝手に改変しない。
- 基本14枚への影響、追加演出の勝手な創作、カイによる撃破、主人公による追撃は認めない。
- VOICEは人間が制作する。エージェントが新規VOICEを作る作業に切り替えてはならない。
