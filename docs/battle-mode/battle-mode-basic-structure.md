# BATTLE MODE 基本演出仕様（8G／1攻防・画像14枚）

> **ステータス：オーナー合意済み（2026-11-14）**
>
> BATTLE MODE の通常バトルにおける、画像制作と演出実装の正本。
> 本書はユーザーが合意した**基本構成**を記録する。エージェントが筋書きを独断で変更してはならない。

## 1. ゲーム性と演出の大原則

- バトルボーナス型の構成として、**8Gをかけて1回の攻防とその結果**を描く。8Gで8回攻撃するものではない。既存作品の素材や固有演出を複製しない。
- バトルの目的は、基本的に**次ROUNDへの継続かGAME OVERかを告知すること**。毎ROUND敵を撃破するゲームではない。
- **1G・2Gは全ルート共通。3Gで先制者が主人公か敵かに分岐する。**
- **4G・5Gは、同じ攻撃側の「必殺技」素材を共用**する。初期版は主人公必殺技／敵必殺技の2種類のみ。
- **6Gは攻撃の命中**。初期版は必ず命中する2種類（主人公→敵／敵→主人公）のみ。回避、ガード、複数回攻撃は追加しない。
- **7G・8Gは被弾側が耐える場面**。同じ被弾側の素材を2Gにわたって共用し、別の攻撃を始めない。
- **8Gの次**に、被弾側の「立ち上がる／倒れる」の結果を告知する。8Gまでの耐える演出と結果告知は分ける。
- **敵は通常、攻撃を受けても立ち上がる。** ただし「20ROUND OVER」かつ「GAME OVER条件成立」の特別終了では、敵を撃破して終えることを許容する。この特別終了の抽選条件・実装は本書では新設しない。
- 表現は**完成静止画＋表示切替＋エフェクト＋SE＋VOICE**を基本とする。画像の人物を大きくスライド・回転させて、格闘動作の代わりにしない。
- カイの援軍、セリーヌの復活は**この14枚に含まない**。独立した追加演出として後から設計する。

## 2. ゲーム進行と分岐

| タイミング | 内容 | 分岐 | 用意する基本画像 |
| --- | --- | --- | --- |
| 1G | 対峙 | 共通 | 1枚 |
| 2G | 対峙・緊張の継続 | 共通 | 1枚 |
| 3G | 先制者の提示 | 主人公先制／敵先制 | 2枚 |
| 4G | 必殺技の攻撃演出（前半） | 主人公攻撃／敵攻撃 | **5Gと共用** |
| 5G | 必殺技の攻撃演出（後半） | 主人公攻撃／敵攻撃 | **4Gと共用で計2枚** |
| 6G | 必殺技が命中する | 主人公→敵／敵→主人公 | 2枚 |
| 7G | 被弾側が耐える | 主人公が耐える／敵が耐える | **8Gと共用** |
| 8G | 被弾側が耐え続ける | 主人公が耐える／敵が耐える | **7Gと共用で計2枚** |
| 8Gの次 | 最終結果を告知 | 主人公が立つ／倒れる、敵が立つ／倒れる | 4枚 |
| **合計** | | | **14枚** |

### ストーリーの読み方

- **主人公先制ルート：** 3G主人公先制 → 4〜5G主人公必殺技 → 6G敵に命中 → 7〜8G敵が耐える → 8Gの次に敵の結果。
- **敵先制ルート：** 3G敵先制 → 4〜5G敵必殺技 → 6G主人公に命中 → 7〜8G主人公が耐える → 8Gの次に主人公の結果。
- 主人公が先制したからといって、7Gや8Gで**追撃、再攻撃、敵の即時撃破**を加えてはいけない。
- 敵が先制したからといって、途中に**主人公の反撃、逆転攻撃**を勝手に加えてはいけない。援軍・復活などは別仕様。
- **攻撃が命中することと、被弾側が最終的に倒れることは別**。6Gに命中しても、7〜8Gは耐え、結果は8Gの次に告知する。

### 共用画像の扱い

- 4Gと5Gは**新しい別攻撃画像を要求しない**。同じ攻撃画像を使い、画角、短い光・衝撃エフェクト、SE・VOICEの再生で前半と後半の見え方を分ける。
- 7Gと8Gも**別画像を要求しない**。同じ「耐える」画像で間をつくり、結末を先に見せない。
- 原則として画像自体が場面の意味を表していること。例えば6Gの命中画像は、拳・打撃と被弾相手の関係が画像単体で読めるように制作する。

## 4. 結果告知の基本線

| 先制側 | 6Gの被弾側 | 8Gの次の結果 | 基本的な意味 |
| --- | --- | --- | --- |
| 主人公 | 敵 | **敵が立ち上がる** | 通常の主人公先制ルート。敵は撃破されず、次ROUNDへつなぐ |
| 主人公 | 敵 | **敵が倒れる** | **20ROUND OVER かつ GAME OVER条件成立**時のみの特別終了表現 |
| 敵 | 主人公 | **主人公が立ち上がる** | 主人公が耐えて継続するルート。援軍・復活の具体演出は別途定義 |
| 敵 | 主人公 | **主人公が倒れる** | 通常の敗北ルート。復活などの救済演出は別途定義 |

- **通常の主人公先制ルートで敵を完全撃破しないこと。**
- 敵の敗北による特別終了は、規定の長期ROUND終了条件が実際に成立するときだけ使用すること。「20ROUND OVER」はオーナー指定の条件表現を保持し、閾値の実装解釈を本書で勝手に変更しない。
- 現行コードのシナリオ分類と上表が1対1で一致しない部分（カイ援軍、セリーヌ復活、ストック救済など）は、**基本14枚の構成とは別のシナリオ仕様で接続する**。未定義の救済挙動を独断で置き換えない。

### 現行実装との対応（参考）

本節は合意済みの基本構成を変更するものではなく、現行コード（`src/engine.ts` の `BattlePattern`／`BattlePhase`、`src/main.tsx`、`src/components/BattleSceneDisplay.tsx`）での接続状況を記録する。

| シナリオ（`BattlePattern`） | 3G〜8G | 8Gの次 |
| --- | --- | --- |
| `hero_attack`（主人公先制） | 主人公先制ルートの画像 | 敵が立ち上がる（No.13）→ CONTINUE |
| `ally_save`（カイ援軍） | 1〜5G敵先制、6〜8Gは専用画像 | [カイ援軍シナリオ仕様](ally-save-scenario.md) の肩叩き → CONTINUE |
| `girl_revive`（セリーヌ復活） | 敵先制ルートの画像 | [セリーヌ復活シナリオ仕様](girl-revive-scenario.md) の復活カットイン → 主人公が立ち上がる（No.11）→ CONTINUE |
| `defeat`（敗北） | 敵先制ルートの画像 | 主人公が倒れる（No.12）で静止（`false_defeat`）→ CHANCE入力 → 敗北確定 → GAME OVER |

- 8G終了時にストックがあれば、`defeat` は1個消費して `girl_revive` に救済される（デバッグで敗北を強制指定した場合を除く）。
- No.14（敵が倒れる）は、現時点では開発用デバッグパネルの「勝利（20ROUND以上のGAME OVER）」指定（`victory_gameover`）でのみ表示される。通常の抽選からの接続は未実装（第6節）。

## 5. 画像制作・演出実装の責務

### 画像制作側

- 各画像が1枚の完成絵として成立し、人物の動作・命中・耐える姿勢・立ち上がる／倒れる結果が明確に読み取れること。
- キャラクター外見は AGENTS.md および docs/characters/README.md の正式デザインガイドに厳密に従う。主人公・ヴォルグの衣装、顔、装備、配色を勝手に変更しない。
- 画像生成の前に14枚の内容・役割を確認し、シリーズ全体で画風、背景、視線、位置関係を整合させる。

### エージェント実装側

- まず本書を読み、**画像14枚の割り当て・場面切替・演出順**を守ること。
- 担当作業は、指定画像の表示切替、必要最小限のズーム・フラッシュ・ヒットストップ等のエフェクト、既存SE・VOICEとの同期、およびゲームUIへの組み込み。
- リールのレバーON／停止イベント、バトルゲーム数、ベル成立・押し順成功、既存の終了・復活分岐との同期に注意すること。**静止画演出のために抽選ロジック・継続率・ストック・払い出し・押し順ナビ・ROUND進行条件を変更しない。**
- 画像に描かれていない**余計な攻撃や反撃をエフェクトだけで追加しない。**
- 他のルートで共有中の画像は使用状況を確認する。新素材へ差し替え、参照がなくなった旧素材のみ削除する。設定ガイド画像を消さない。

## 7. 変更管理

この基本構成の変更（Gごとの役割、分岐、画像枚数、通常の敵の生存方針、特別終了条件）は、**事前にオーナーの明示的な合意を得てから**本書を更新すること。画像生成エージェントや実装エージェントの裁量で変更しない。
